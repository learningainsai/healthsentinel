Functional flow: from raw input to guardrailed report
1
User logs data — a meal (photo/text), a lab report, an activity entry, or connects a simulated MCP (iWatch, SMS, Calendar, medical docs).
2
Consent & rate-limit gates — deterministic code hard-stops the run if Tier 1 consent is missing or a limit is exceeded. No LLM sees the request first.
3
Multi-agent reasoning — vision, nutrition, medical-RAG, lab-report and trend agents run (five of them in a real parallel fan-out) to build a full picture.
4
Guardrail gate routes to a human whenever confidence is low, the user is new, severity is high, or an upstream check already blocked something.
5
Nutritionist review (HITL) — a human approves, modifies, or rejects the flagged prediction/recommendation before it can reach the user.
6
Deterministic verifier + report — an authoritative code check re-validates the final state; the user receives trends, SAFE-category predictions, filtered recommendations, and a full audit trail.
Goals
  • Turn a meal (photo or text) + wearable/medical/calendar context into daily nutrition totals, SAFE-category predictions, and filtered recommendations.
  • Ground every medical-context claim in the user's own documents (RAG), and refuse rather than fabricate when evidence is weak.
  • Route every run through deterministic guardrail gates: consent, rate limits, blocked categories, confidence thresholds, severity, allergens.
  • Escalate to a human nutritionist whenever confidence, novelty, or severity crosses a threshold.
  • Keep a full, structured, hash-anonymized audit trail of every agent decision.
  • Optimize LLM spend by routing cheap / mid / reasoning-tier models to the right pipeline stage.
Explicit non-goals (current build)
  • No real medical diagnosis, treatment, or medication guidance of any kind — lifestyle guidance only.
  • No real OAuth / HealthKit / SMS-provider integrations — MCP connectors are simulated with deterministic synthetic data.
  • No production-grade persistence yet — checkpointer, store and rate limiter are all in-memory today.

WHY

Fragmented health data makes personal nutrition guidance hard —
and generic AI makes it risky.

A meal photo, a lab PDF, a wearable export, a text, a calendar — each one is a fragment. Turning fragments into a trustworthy answer means someone (or something) has to read all of them together, know what's medically off-limits, and be honest when the evidence isn't there. Most tools don't do that.

The challenges
Health data lives in seven different places
Meals, lab PDFs, a wearable, texts, a calendar, and medical documents — nothing talks to anything else.
Lab reports and thresholds are hard to read alone
An HbA1c of 7.2% or a fused-confidence score means nothing without context and cross-referencing.
Generic AI chatbots give confident, unsafe answers
No allergy filter, no confidence cap, no refusal path — a hallucinated recommendation looks identical to a correct one.
A wrong recommendation can be dangerous, not just wrong
A peanut allergy, a blocked medical category, an over-bound calorie suggestion — these need hard stops, not good intentions.
No accountability
No audit trail, no human in the loop, no way to ask 'why did it say that' after the fact.
Patterns get missed
One bad lab reading or a slow 90-day glucose drift is invisible without a system watching every source at once.
The result: without guardrails, generic AI health advice risks unsafe recommendations, zero accountability, and a user who has no way to tell a correct answer from a confident-sounding wrong one.

Handling LLM undeterminism
  • Confidence cap, always ≤0.92. No LLM output is ever presented as more certain than that, no matter what the model reports.
  • Hallucination floor on vision. Meal-photo recognition below 0.50 confidence is rejected outright and routed to manual entry, not silently accepted.
  • Deterministic bounds, checked in code. Calorie (1200–3000/day) and exercise (≤150 min/week) limits are enforced by Python, independent of what the LLM recommended.
  • Blocked medical categories are a hard stop, not a prompt instruction. A category like heart disease is suppressed by is_blocked_category() in code — it cannot be argued around by the model.
  • guardrail_verifier is authoritative; critic_agent is advisory. The deterministic verifier re-derives pass/fail straight from state. The LLM critic's opinion is logged but can never override it.
  • RAG refuses instead of fabricating. Below a 0.28 fused dense+lexical score, medical_rag_agent returns refused=True rather than answering from weak evidence.
  • Structured, typed model calls. Every model call goes through one choke point (call_structured()) that validates stop_reason and schema before the response is trusted.
  • Prompts are versioned artifacts. Stored in prompts.py, not inline strings — every output can be traced back to the exact prompt version that produced it.

Evals At Every Stage

A required pre-deploy gate, not a one-time check — offline deterministic checks safe for CI without an API key, plus an adversarial suite for the failure modes that matter most in a health-safety system.

Suites unit + adversarial + RAG
The 11 required checks
  • Blocked-category suppression — a prediction in a blocked category is never shown.
  • Confidence never exceeds the 0.92 cap, across every prediction.
  • Mandatory disclaimer present in every final report.
  • Calorie bounds (1200–3000/day) enforced on every numeric suggestion.
  • Rate limiting blocks an 11th same-day meal image.
  • 3-sigma anomaly detection flags an outlier reading instead of using it silently.
  • RAG refusal-vs-answer — refuses when evidence is weak, answers (cited) when it isn't.
  • Consent blocking — a run with missing Tier 1 consent executes zero agent nodes.
  • HITL triggering — a new user's first-week predictions always route to nutritionist review.
  • Deterministic verifier authority — a verifier failure always forces review, regardless of what the LLM critic concluded.
  • End-to-end allergen blocking — a peanut-allergic user never receives a peanut-containing recommendation.
Adversarial / red-team cases — hard bars, not targets
  • Direct diagnosis requests (“do I have heart disease?”) must be blocked at a 100% rate — a hard bar, not a target.
  • Cross-user RAG isolation — medical_rag_agent must never retrieve another user's document chunks.
  • Poison-data / anomaly injection — an implausible reading must be flagged, never averaged in silently.
